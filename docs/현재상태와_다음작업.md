# 현재 상태와 다음 작업

## 인계 시점

- 사용자가 현재 진행 상태를 Claude에게 넘겨달라고 요청하여 0.11.0을 체크포인트[이어서 작업할 수 있는 저장 상태]로 묶었습니다.
- 현재 코드의 빌드와 단위 검사는 통과했습니다.
- 실제 경로를 설정해 출발부터 통과까지 연결한 검증은 아직 완료하지 않았습니다.
- 최신 APK는 원본 Pleos 에뮬레이터에 설치되어 있고, 앱이 실행되는 것까지 확인했습니다.

## 구분해야 하는 기능 범위

- 전체 경로 검색: 미구현. 현재 SDK 공개 표면에서 경로 전체 좌표 제공 API를 확인하지 못함.
- 현재 위치: 공개 `getCurrentLocationInfo()`와 콜백 사용.
- 목적지와 경유지 시간: 공개 `getDestinationInfo()`, `getWaypointInfo()`와 콜백 사용.
- `DrivingInfo`: 이미 확인한 장소의 이름과 순서가 맞을 때만 남은 거리와 시간을 갱신.
- 경로 변경과 취소: 기존 위치 및 장소 정보를 비우고 새 정보를 기다림.
- 주변 장소: 앱에 포함된 위치 목록과 현재 좌표 비교. 인터넷 장소 검색이 아님.
- 통과: 실제 접근 후 최소 거리보다 60m 이상 멀어지는 이동 샘플 2개로 판단. 시야 감지는 아님.
- 12초 이상의 위치 공백이나 비현실적인 좌표 점프는 통과 이력을 초기화.
- 시간만 0초가 된 것은 도착으로 처리하지 않음. 도착 이벤트와 근처 위치가 함께 필요.
- 지도 기준점은 실제 출입구나 정확한 관측 지점이 아닙니다. 현장 검증으로 반경을 조정해야 합니다.

## 다음 작업 1: 실제 SDK 의미 확인

- `NaviMode.ROUTE_GUIDING` 또는 `SIMULATION_GUIDING` 상태에서 실제로 위치가 갱신되는지 확인합니다.
- `DestinationInfo.remainTime`, `WaypointInfo.remainTime`, `DrivingState.duration`이 예상한 초 단위이며 각 지점까지 남은 시간인지 확인합니다.
- 현재 코드는 이 값을 초 단위로 사용합니다. 이번 SAFE_GUIDING 조회만으로 단위와 주행 시 의미까지 입증하지는 못했습니다.
- `CurrentLocationInfo.routeId`가 재탐색 때 어떻게 변하는지 확인합니다.
- `isRouting`의 의미는 추측해서 조건에 사용하지 않았습니다. 현재 모드 값으로 안내 여부를 구분합니다.
- 목적지 변경, 경유지 도착, 재탐색 콜백 순서가 겹칠 때 이전 정보가 새 경로에 섞이지 않는지 점검합니다.
- SDK 위치 응답에 정확도와 원본 측정 시각이 없어 현재는 콜백 수신 시각으로 유효 시간을 판단합니다. SDK가 캐시 위치를 반복 반환하는 경우를 별도로 점검해야 합니다.

## 다음 작업 2: 음성 서비스와 권한

- 정확한 위치 권한과 위치 설정을 켠 뒤 `CuratorDriveService` 시작을 확인합니다.
- 화면을 벗어나도 서비스와 알림이 유지되는지 확인합니다.
- 알림의 `여행 끝내기`, 일시 정지, 다시 시작이 실제로 동작하는지 확인합니다.
- 주행 제한 시 영상과 터치 화면은 제한하고 음성은 이어지는지 확인합니다. 실제 차량 및 심사 기준 승인을 받은 상태는 아닙니다.
- 현재 서비스는 외부 AI와 마이크를 사용하지 않습니다.
- 해결함[0.12.0]. `VoiceGuide.speak`는 이제 한 번의 결과만 돌려줍니다. 끝까지 말하면 `onDone`, 실패나 교체나 오디오 우선순위 상실로 끝나면 `onAborted`입니다. 두 호출자[`CuratorDriveService`, `MainActivity`]는 둘 중 어느 쪽이 와도 EXPLAIN을 벗어납니다.
- 서비스에는 추가로 시간 제한 감시가 있습니다. 두 콜백이 모두 오지 않아도 해설 길이에 맞춘 시간이 지나면 EXPLAIN을 벗어납니다. 최대 60초입니다.
- 벗어나는 경로는 아이의 `이제 내가 해 볼래!` 버튼과 같은 `afterExplanation`입니다. 중단을 들었다고 기록하지 않습니다. `NarrationRecoveryTest` 8개가 이 판단을 고정합니다.
- 남은 확인: 실제 기기에서 음성 실패를 일으켜 이 복구가 실제로 동작하는지 봐야 합니다. 현재는 단위 검사와 코드 검토까지만 했습니다.
- 보호자 창이나 음성 답변으로 자동 해설을 멈췄다가 닫을 때 EXPLAIN 상태의 이어 듣기 동작을 점검하세요.
- 음성 중단을 ‘아이가 해설을 끝까지 들음’으로 기록하면 안 됩니다. 현재 `explained`는 해설 상태 진입 시 표시되는 값입니다.
- 서비스 종료 후 Activity가 계속 연결되어 있는 경우와 다시 시작하는 경우도 검사하세요.

## 다음 작업 3: 실제 운행 시나리오

1. 지원 목적지 또는 경유지의 남은 시간 301초에서 질문하지 않음.
2. 300초 이하로 들어오면 한 번만 질문.
3. 답하지 않아도 접근 및 통과가 진행됨.
4. 아이가 안 보인다고 하면 그대로 존중하고 해설은 들을 수 있음.
5. 통과 또는 확인된 도착에서 짧은 해설.
6. 음성 내비 안내가 끼면 겹쳐 말하지 않음.
7. 길이 바뀌면 이전 장소의 잘못된 통과 해설이 나오지 않음.
8. 위치 신호가 오래되면 알림을 보류하고 같은 지점에서 반복하지 않음.
9. 역할 놀이 후 다음 장소로 넘어감.

## 이후 확장

- 공모전 측에 실제 선택 경로의 좌표 목록과 구간별 시간을 받을 수 있는 공식 방법을 문의합니다.
- 경로가 확보되면 경로와 가까운 장소를 고르고, 도로 위의 통과 지점까지 시간을 계산합니다.
- 전국 명소와 오래된 가게는 출처, 좌표, 역사 기록, 갱신일을 갖춘 데이터 공급을 별도로 구성합니다.
- AI가 오래된 가게의 연혁이나 건축 기법을 임의로 만들어 설명하지 않도록 합니다.
- 지금은 네트워크 자동 검색, 전국 장소 확장, 경로 전체 좌표 연동이 구현된 것처럼 표시하지 않습니다.
