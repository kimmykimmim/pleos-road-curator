# 0.38.0 아이 관점 추가 점검 인계

사용자 요청: 현재 완성된 앱을 아이 관점에서 실행해 문제점과 작은 수정안을 설명한 뒤, 그 7가지를 지금 즉시 [코드구현] 세션에 전달.

## 점검 기준과 범위

- 커밋 ec2d7aa, 0.38.0/versionCode 40. 최신 debug APK를 빌드해 기존 설정을 유지하며 Pleos 에뮬레이터 emulator-5554에 설치.
- 숭례문 자연 진행: 무응답 → 관찰 → 통과 해설 → 저장된 가족 이야기 → 역할 놀이. 광화문/청진옥은 정차 시연의 시점 이동으로 필요한 장면 확인.
- 한국어/영어 화면, 안 보여/봤어, 청진옥 퀴즈에서 The 1990s 선택, 역할 놀이 선택을 직접 실행.
- 음성 제어 문장은 실제 컴파일된 domain 클래스를 Java에서 호출해 검사. 실제 STT나 아이 목소리를 검증했다는 뜻이 아님.
- 실제 아이 사용, 뒷자리 가독성, 실제 내비 주행, 오디오 청취 품질은 미검증.
- 앱 코드는 변경하지 않음. 점검 중 바꾼 언어/관심사 등을 사용자 10의 shared_prefs 백업으로 복원하고 각 파일 바이트 일치 확인. 가족 기록 원문과 설정 백업은 인계 증거에 복사하지 않음.

## C01 우선 수정 제안 — 자연스러운 중단 표현 누락 [로직 재현]

BackSeat.kt SpokenReply.of에서 다음 결과:

```
그만 => Rest
그만해 => OwnWords(text=그만해)
쉬고 싶어 => OwnWords(text=쉬고 싶어)
잠깐만 => OwnWords(text=잠깐만)
잠깐 쉴래 => Rest
그만 듣고 싶어 => Rest
I want a break => OwnWords(text=I want a break)
다음에 또 보고 싶어 => OwnWords(text=다음에 또 보고 싶어)
```

아이가 멈추려고 하는 말을 답변으로 받아 대화를 이어갈 수 있음. 대표적인 아이 말투를 중단 명령으로 보강하되, 이전 부분 문자열 오판 회귀를 막을 것. 무조건 '그만' 포함 문장을 모두 중단으로 잡는 방식은 피할 것.

## C02 우선 수정 제안 — 모르겠어의 대화 종료 판단 미반영 [로직 재현]

VoiceTalk.reply(sungnyemun, 모르겠어, 1, Korean, HISTORY)는 askAgain=false를 반환.
그러나 RouteCurator.heard는 reply.line만 취하고 expectsAnswer(next,1)는 true. 화면의 재청취 조건과 종료 판단이 어긋남.

```
모르겠어 => TalkReply(... askAgain=false); engine.expectsAnswer=true
```

다시 같은 질문을 실제로 음성으로 했다고 주장하는 것은 아님. 확인한 결함은 종료로 판단한 응답 뒤에도 답을 더 기다리는 경로가 열려 있다는 것. 종료 결정을 진행 상태/마이크 재개 판단에 반영해 아이를 추가 응답 대기에서 풀어주는 수정 제안.

## C03 관찰 대상 변경 [화면 확인]

숭례문 10번째 만남의 찾기 질문: '지붕 끝이 하늘로 올라갔어, 아니면 아래로 내려왔어?'
가까워진 WATCH: '큰 지붕 아래 둥근 통로를 찾아볼래?'

아이는 지붕 끝을 보려다가 다른 것을 찾으라는 안내를 받음. 현재 질문의 관찰 대상을 WATCH까지 유지하는 작은 콘텐츠 수정 제안. 모든 장소를 특정 분야에 억지로 연결하라는 뜻이 아님.
증거: 02-first-question.png, 04-flow.png. 스냅샷의 XML과 PNG는 약간의 캡처 시차가 있어 04-flow.xml은 직전 PREDICT이고 PNG에 WATCH가 나옴.

## C04 창밖보다 화면으로 답하기 쉬움 [UX 관찰과 제안, 실제 아이 효과 미검증]

관찰 단계에도 지붕/통로가 보이는 큰 사진과 버튼이 함께 있음. 아이는 화면 사진으로 답할 수 있고, 뒷자리 말하기도 현재 기본 꺼짐.
관찰 중 사진을 작게 하고 한 가지 창밖 찾기 안내를 강조하는 소규모 변경을 제안. 사진의 장소 식별 도움은 유지할 가치가 있으며 전면 삭제 제안 아님. 화면 크기 조정의 실제 효과는 아이 사용으로 확인할 것. 제품 선택 항목이므로 확정 결함 C01/C02/C07과 구분.

## C05 퀴즈 질문 중 정답 태그 노출 [화면 재현]

영어 청진옥: 'When did Cheongjinok first open?' / '1937' vs 'The 1990s'.
같은 화면 아래에 #openedin1937 표시. 한국어 태그도 #1937년개업.
숭례문도 #밤에닫는문이 해당 퀴즈 답을 먼저 보여줄 수 있음.
해설 전에는 현재 질문의 답을 알려주는 태그를 숨기거나, 태그 전체를 해설 이후에 표시하는 수정 제안.
증거: 18-cheongjinok.png/json. The 1990s 선택 후 비난 없이 1937을 설명하는 점은 확인된 장점(19-quiz-alternative).

## C06 숭례문 설명의 경복궁 사진 [화면과 출처 확인]

숭례문 해설에 SceneScraps.GATE의 gate-guard.jpg가 나오고 '문을 지키던 수문장의 교대 의식'이라고만 표기됨.
원본 Commons의 분류는 Changing of the Guard at the Gyeongbokgung. 숭례문의 실제 장면으로 오해할 수 있음.

https://commons.wikimedia.org/wiki/File:Royal_Guard-Changing_Ceremony_of_Joseon_in_2018.jpg

'경복궁 수문장 교대식 예시'라고 명시하거나 해당 장소 사진으로 교체 제안. 동일 visual GATE를 광화문과 공유하는 점 고려. 사진 이용권 문제를 제기하는 항목이 아님.

## C07 영어 직접 말하기 확인창 한국어 고정 [화면 재현]

아이 설정 English → 질문 화면의 'I think… (say it out loud)' 누름.
제목은 영어지만 본문은 '확인을 누르면 이번 답변을 듣기 시작해요…', 버튼은 '나중에'/'이야기할게'.
MainActivity.listen()의 고정 문구와 openMic() 상태 문구도 확인 필요. 보호자 메뉴가 한국어인 점과는 별개의 아이용 경로.
선택 언어로 본문/버튼/상태까지 맞추는 수정 제안.
증거: 16-english-mic-confirm.png/json.

## 인계 우선순위

C01/C02를 먼저, 다음 C03/C04로 관찰 흐름 개선. C05/C06/C07도 작게 고칠 수 있는 별도 항목.
코드 담당자는 각 항목을 현재 코드에서 재확인하고 결함 수정과 UX 제안을 구분할 것. 큰 재설계나 외부 AI 도입을 요청하는 인계가 아님. 구현 범위와 제품 선택은 원 대화의 사용자 지시를 따를 것.
