## 1. 기능 오류보다 먼저 지켜야 할 앱의 목표

차량 이동 시간을 아이가 창밖의 실제 세상에 호기심을 갖고 자기 생각을 펼치는 시간으로 만든다.
장소를 설명하는 데서 끝나지 않고, 아이가 좋아하는 것과 실제 세상이 연결되는 경험이 목표다.
화면은 다시 창밖을 보게 돕고, 보호자는 아이와 이야기를 함께 나눌 수 있어야 한다.

사용자가 말한 핵심 요구:

- 과학, 역사, 예술 등 관심 분야와 공룡 등 구체적인 취향에 따라 질문의 주제와 내용이 달라진다.
- 하나의 공통 대상만 정해 모든 분야에 억지로 끼워 맞추라는 뜻이 아니다.
- 보호자는 아이의 관심사와 사용하는 언어를 알고 있으므로 이를 설정에 반영한다.
- 아이가 어떤 답을 해도 절대 “틀렸다”고 말하지 않는다.
- 생각을 존중하는 것과 사실과 다른 말을 정답으로 인정하는 것은 구분한다.

따라서 검토 기준은 다음 순서다.

1. 아이가 창밖의 장소를 실제로 궁금해하게 되는가?
2. 아이가 자기 관심사에 맞는 질문과 대화를 경험하는가?
3. 후석에서 손을 뻗지 않고 자연스럽게 참여할 수 있는가?
4. 대답하지 않거나 모른다고 해도 부담 없이 경험이 이어지는가?
5. 보호자의 조작 없이도 주요 흐름이 이어지고, 필요한 설정은 출발 전에 발견할 수 있는가?

## 3. 실제 동작 오류 및 연결 누락

### B01. 실제 내비 모드에 자동 음성 답변 흐름이 연결되지 않음 — 높음

**근거: 코드 확인. 실제 주행 재현 아님.**

- `CuratorDriveService.kt:87`에서 `VoiceGuide(initializeListening=false)`로 생성한다.
- 서비스의 `narrate()` 완료 처리는 다음 설명 단계 진행에 연결되고, 질문 후 마이크를 여는 처리에는 연결되지 않는다.
- `MainActivity.apply()`는 `live`이면 서비스에 넘기고 바로 반환한다. 시연에서 쓰는 질문 후 `openMic()` 경로를 지나지 않는다.
- `driveObserver`는 상태를 복사하고 화면을 다시 그리며 마이크를 열지 않는다.

**목표에 주는 영향:** 뒷자리 말하기 설정이 있어도 실제 여행에서 아이가 그냥 대답하는 경험으로 이어지지 않는다. 시연과 제품의 핵심 경험이 다르다.

**수정 후 확인:** 차량 제한을 준수하는 지원 상태에서, 보호자가 음성 참여를 켰다면 실제 내비 모드에서도 질문 → 한 번 듣기 → 아이 말에 반응하는 흐름이 연결되어야 한다. 배경 마이크를 무조건 켜거나 차량 제한을 우회하라는 제안이 아니다. 지원하지 않는 상태는 보호자에게 정확히 안내한다.

관련: `MainActivity.kt`의 `apply`, `driveObserver`; `CuratorDriveService.kt`의 `onCreate`, `narrate`.

### B02. 직접 말하기를 누르면 시연이 멈추고 자동 재개 경로가 없음 — 높음

**근거: UI 진입 및 코드 확인.**

1. 시연의 질문 화면에서 `내 생각엔… (직접 말하기)`를 누른다.
2. 추가 확인창이 나타난다. `04-mic-consent.png` 참조.
3. `listen()`이 `playing=false`로 설정한다.
4. 취소, 듣기 종료, `predict()` 처리에 시연을 자동 재개하는 연결이 없다.

**목표에 주는 영향:** 참여하려고 누른 조작 때문에 여행이 멈추며, 보호자 메뉴에서 재개해야 할 수 있다. 후석 아이에게 “이제 무엇을 해야 하지?”라는 상황이 생긴다.

**수정 후 확인:** 원래 재생 중이었다면 취소 또는 답변 후 적절히 이어지고, 원래 쉬는 중이었다면 그 의도를 유지한다. 보호자가 이미 자동 듣기에 동의한 경우와 최초 마이크 동의는 구분한다.

관련: `MainActivity.kt:393`의 `listen`, `openMic`, `accept`, `apply`.

### B03. 한국어 일반 문장을 제어 명령으로 오해함 — 높음

**근거: 기존 클래스 호출로 재현.**

| 입력 | 실제 결과 | 의도상 필요한 처리 |
|---|---|---|
| 다음에 또 보고 싶어 | `Skip` | 감상 또는 답변으로 처리 |
| 다시 지으면 좋겠어 | `Repeat` | 상상 답변으로 처리 |

`SpokenReply.of()`는 제어 단어가 문장에 포함되면 답변보다 우선 처리한다. 특정 단어 포함 여부만으로 명령과 생각을 구별할 수 없다.

**목표에 주는 영향:** 아이가 생각을 말했는데 설명이 넘어가거나 엉뚱한 말을 반복한다. 자기 말을 듣지 않는다고 느낄 수 있다.

**수정 후 확인:** 명확한 짧은 명령은 계속 동작하면서 위 문장은 답변으로 남아야 한다. 모호한 말은 강제로 건너뛰기보다 확인하거나 답변으로 보수적으로 처리한다.

관련: `domain/BackSeat.kt:79–98`. 증거: `parser-probes.txt`.

### B04. 영어 관찰 응답과 제어 명령이 동작하지 않음 — 높음

**근거: UI 재현 및 로직 재현.**

UI 재현:

1. 보호자 → 아이 설정 → English 저장.
2. 한강 시연 → 보호자 → 시점 이동 → 롯데월드타워 가까이.
3. 관찰 화면에는 `Say “I see it”` 취지의 안내와 `I see it!` 버튼이 있다.
4. 보호자 → 말 대신 입력에서 `I see it` 입력 후 전하기.
5. 관찰 응답이 처리되지 않고 한국어로 `보이면 ‘봤어’, 안 보이면 ‘안 보여’라고 알려줘`가 표시된다.

증거: `09-english-watch.png`, `17-english-seen-result.png`.

로직 재현: `stop`, `again`, `next`는 각각 `OwnWords`로 처리된다. 제어 명령 목록과 관찰 응답 정규식이 한국어뿐이다.

**목표에 주는 영향:** 화면이 안내한 말을 그대로 해도 통하지 않는다. 영어 사용자에게 사용 중단이나 반복 요청도 통하지 않을 수 있다.

**수정 후 확인:** 설정 언어에 맞는 관찰 응답, 중단, 반복, 넘기기 표현이 동작해야 한다. 영어 입력의 대소문자와 구두점도 일관되게 정규화한다. 화면 버튼을 누르는 것만으로 통과 판정을 하지 않는다.

관련: `domain/BackSeat.kt`, `MainActivity.kt`의 `accept`.

### B05. 영어 “모르겠어”를 이해하지 못하고 대화를 계속함 — 중간

**근거: 기존 클래스 호출로 재현.**

`VoiceTalk.reply(영어 롯데월드타워, "I don't know", 1)`은 모른다는 응답 분기로 가지 않는다. 말을 되읽고 `That is a way to look at it`이라 한 뒤 건물에 바람이 불면 어떻게 될지 다시 묻는다. `unsureCues`에는 한국어만 있다.

부수적으로 `wind`는 바람 대본을 선택하지만 `Wind`는 되읽기 기본 응답으로 빠진다.

**목표에 주는 영향:** 아이가 모른다거나 더 답하기 어렵다는 뜻을 밝혀도 질문이 계속된다.

**수정 후 확인:** 언어에 맞는 모름 표현을 받아 짧게 안심시키고 설명 또는 관찰로 이어간다. 참고로 `TalkReply.askAgain`의 종료 의도가 `expectsAnswer()`와 실제 마이크 재개 판단까지 전달되는지도 확인할 필요가 있다. 이 마지막 연결 문제는 별도 실행 재현하지 않았다.

관련: `domain/VoiceTalk.kt`, `RouteCurator.heard`, `RouteCurator.expectsAnswer`.

### B06. 영어 설정에서도 일부 아이용 문구가 한국어로 남음 — 중간

**근거: 화면 및 코드 확인.**

- B04의 관찰 재요청 문구는 실제 화면에서 한국어로 확인했다.
- `MainActivity.populate()`의 설명 요약은 `몸통과 바깥 기둥이 힘을 나눠요` 등 한국어 고정 문구다.
- `memoryCard()`는 한국어 기본 장소 목록과 `처음 생각`, `직접 봤어` 등의 고정 문구를 사용한다.
- 직접 말하기 확인창도 한국어다. 보호자 전용 화면이 한국어인 점과 아이가 마주하는 안내가 섞이는 점을 구별해 판단한다.

**수정 후 확인:** 아이에게 보여 주거나 들려주는 안내, 오류, 해설 요약, 기억 카드가 설정 언어를 따른다. 보호자 화면 번역을 일괄 의무화하라는 뜻은 아니다.

## 4. 앱 목표에 비춘 제품 개선 제안

아래는 결함 수정과 구분해야 한다. 사용자와 범위를 정한 뒤 구현할 제안이며, 외부 AI 도입이나 콘텐츠 전면 교체를 전제로 하지 않는다.

### U01. 관심사에 맞춘 질문과 후속 대화가 분리됨 — 중요

**근거:** `Rounds.promptFor()`는 관심 분야를 보고 질문을 고른다. 그러나 `VoiceTalk.reply()`는 현재 질문 또는 분야를 받지 않고 장소별 `talk`만 사용한다. 롯데월드타워 대화는 주로 바람과 구조를 다루고, 기본 응답도 바람 질문으로 돌아간다.

**영향:** 예술에 관심 있는 아이가 건물 모양을 상상해 답해도 과학 대화로 돌아갈 수 있다. 첫 질문만 맞춤형이고 이어지는 경험은 공통 대본이 된다.

**개선 방향:** 현재 질문, 분야, 아이가 말한 내용을 기준으로 이어 말할 대본을 고른다. 최소한 예술 질문의 모양 답변이 무관한 바람 질문으로 회귀하지 않게 한다. 장소마다 정직하게 가능한 주제를 사용하고, 분야를 맞추려고 사실을 지어내지 않는다.

**검증 예:** 예술 관심사로 롯데월드타워의 모양 질문을 받고 “동그란 모양”이라고 답하면 모양이나 표현을 탐색하는 말이 이어진다. 과학 관심사는 과학 질문으로, 역사 관심사는 역사 질문이 실제로 준비된 장소에서 그 질문으로 이어진다.

### U02. 설정에 표시되는 취향과 준비된 콘텐츠가 일치하지 않음 — 중요

**근거:** `FavouriteTopic`은 음악과 로봇을 포함한다. 현재 한국어 장소별 `bridges`에는 음악, 로봇 연결 문구가 없다. 구체적인 취향은 주로 질문 앞에 한마디를 덧붙이는 데 사용된다.

**영향:** 보호자가 아이가 좋아하는 것을 골라도 경험이 달라지지 않을 수 있다. 공룡 등도 단순 인사말에 그치면 취향을 활용한 탐색으로 느끼기 어렵다.

**개선 방향:** 지원되는 선택지를 정직하게 안내하거나 실제 연결 콘텐츠를 보강한다. 지원되지 않는 분야를 억지로 장소와 연결하지 않는다.

### U03. 출발 전에 핵심 설정을 찾기 어려움 — 중요

**근거:** `02-menu.png`. 아이 설정과 뒷자리 말하기가 시연 제어, 출처, 가족 기록 등과 함께 긴 보호자 메뉴 아래쪽에 있다. 자동 음성 답변은 기본 꺼짐이다.

**영향:** 기본 상태로 시작하면 후석 아이는 화면을 눌러야 답할 수 있다. 보호자가 설정의 존재를 모를 가능성이 있다.

**개선 방향:** 출발 전에 아이의 언어, 관심사, 말로 답하기 동의를 짧게 확인할 수 있게 한다. 마이크 동의를 자동으로 대신하거나 운행 중 보호자 조작을 유도하지 않는다.

### U04. 설명 난이도를 아이 수준에 맞출 수 없음 — 중간

**근거:** 대상은 6~8세지만 `ChildProfile`에는 나이, 이해 수준, 설명 길이 설정이 없다. 해설에는 아웃리거, 벨트트러스, 커튼월 등의 용어가 연속 등장한다.

**영향:** 관심 분야가 같아도 이해 수준에 따라 설명이 어렵거나 지루할 수 있다. 실제 아이 대상 관찰이 필요하며, 현재 내용이 반드시 이해 불가능하다고 확정한 것은 아니다.

**개선 방향:** 첫 설명은 짧고 익숙한 비유로 제공하고, 더 궁금할 때 자세히 들을 수 있게 한다. 정교한 연령 모델보다 최소한의 난이도나 길이 선택부터 검토한다.

### U05. 같은 길을 반복 이용할 때 콘텐츠가 빨리 순환함 — 중간

**근거:** 앱에 기본 장소 6개가 있고 질문은 유한한 목록을 순환한다. `Rounds.promptFor()`는 선호 분야 질문을 먼저 배치한 뒤 비선호 분야 질문도 순환하며, 해설과 역할 놀이는 반복 횟수에 따라 달라지지 않는다.

**영향:** 매일 같은 길을 다니는 아이에게는 새 질문을 받는 기간이 짧을 수 있다. 다만 이번 점검은 장기간 아이의 흥미 감소를 측정한 연구가 아니다.

**개선 방향:** 새 질문뿐 아니라 관찰 과제, 역할 놀이, 짧게 듣기 등을 적절히 변주한다. 앱이 계속 질문하기보다 조용히 창밖을 보는 시간도 허용한다.

### U06. “틀렸다”를 피하면서 사실을 어떻게 안내할지 보완 필요 — 중간

**근거:** 기본 대본에 금지어와 부드러운 설명 분기가 있다. 다만 준비된 분기로 분류되지 않은 말은 그대로 되읽고 `그렇게 볼 수도 있겠다` 등의 기본 문구로 돌아간다.

**영향:** 아이의 사실과 다른 말을 이해하지 못했을 때도 동의하는 인상으로 들릴 수 있다. 실제로 모든 오개념에 동의한다고 입증한 것은 아니다.

**개선 방향:** 상상, 취향, 사실 주장을 구분한다. 이해하지 못한 사실 주장은 맞다고 인정하지 않고, 생각의 이유를 존중하거나 검증된 설명으로 연결한다. “틀렸어” 금지 원칙은 계속 유지한다.

## 5. 코드구현 Claude에게 요청하는 사용 방법

1. 먼저 이 문서의 목표와 증거를 읽고 현재 코드에서 다시 확인한다. 검토 기준 커밋 이후 변경이 있으면 이미 해결된 항목을 구분한다.
2. B01~B04를 우선 확인한다. 실제 내비 연결, 후석 답변, 의도 오해는 핵심 경험을 직접 깨뜨린다.
3. B05~B06의 언어와 대화 종료 동작을 점검한다.
4. U01~U06은 제품 제안이다. 모두 즉시 구현하기로 승인된 것으로 해석하지 않는다. 특히 관심사별 대화 방향, 최초 설정, 콘텐츠 확대는 사용자의 판단이 필요한 설계 선택을 짧게 제시한다.
5. 차량 화면 제한, 외부 전송 금지, 현재의 사실 검증 원칙을 유지한다. 외부 생성형 AI나 새 서버를 임의로 추가할 이유는 없다.
6. 수정한다면 기존 346개 검사 통과만으로 완료 처리하지 말고 해당 문제의 재현 문장과 화면 흐름이 실제로 개선됐는지 확인한다. 실제 차량에서 확인하지 못한 것은 별도로 표시한다.

이 전달 자체는 문제점 문서 공유 요청이다. 수신만으로 모든 제안의 구현, 배포, 커밋 또는 푸시를 승인한 것으로 해석하지 않는다.
