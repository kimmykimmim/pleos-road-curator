# 0.44.0 숯과 라임 시연 및 화면 평가

## 실행 조건

- 기준 커밋: `14fecb8`, 버전 `0.44.0`, versionCode `46`.
- 기기에 남아 있던 0.43.0을 확인한 뒤 `:app:assembleDebug`로 빌드하고 `adb install -r`로 설치했다. 설치 후 dumpsys의 버전 이름과 코드를 확인했다.
- Pleos Connect v2.1.0 에뮬레이터 `emulator-5554`, 사용자 10, 정차 고정 경로 시연.
- 보호자 메뉴에서 질문을 처음 만남으로 되돌리고 확인 버튼을 눌렀다. `rounds-start.xml`이 빈 map인 것을 확인한 뒤 앱을 다시 열었다. 가족의 기억은 초기화하지 않았다.
- 서울을 가로지르는 길을 한 번 선택했다. 녹화 중 시점 이동이나 응답 조작 없이 가상 시간 10배로 자동 진행했다.
- 180초 제한, 비트레이트 8,000,000으로 나누어 녹화한 뒤 각 제한 시간이 끝나고 파일을 가져왔다. 실제 녹화 구간과 실행 시각은 `capture-log.json`에 기록했다.
- 화면은 약 12초 간격으로 캡처했다. `tNNN.png`의 숫자는 스크립트 시작 후 실제 경과 초이다.

대표 캡처의 원본은 차례대로 `t014`, `t086`, `t170`, `t230`, `t302`, `t374`이다. 마무리 카드는 `t446`이다. 처음부터 끝까지 한 경로를 진행했고, t446에서 여섯 장소 저장값이 모두 1인 것을 확인했다. 첫 만남의 마무리 카드에 2번째 만남이 뜨는 문제는 관찰되지 않았다.

발표자료의 이전 색 이미지와 영상 임베드를 모두 새 자료로 교체했다. 과거 기능 검사 기록은 이전 버전 기록이라고 표시했다. 앱 소스는 수정하지 않았다.

## 관찰한 화면

- 질문 카드의 본문, 라임 주 버튼의 어두운 글자, 회색 보조 버튼은 읽을 수 있었다.
- 숯 바탕의 장소 이름과 태그는 잘 구분되었다. 여섯 칸의 경로 막대에서 현재 장소의 라임 표시가 다른 장소와 구별되며, 확인한 화면에서 이름 겹침이나 잘림은 없었다.
- 사진 위 라임 동그라미와 화살표는 얇은 선으로 표시되어 건물과 간판을 가리지 않았다. 사진 전체를 덮는 밝은 면이나 섬광은 관찰하지 않았다. 실제 차량에서 눈부심이 없는지는 이 결과만으로 판단하지 않는다.

## 색 대비와 가독성

색상 상수의 sRGB 상대 휘도로 계산한 전경/배경 대비이다. 영상 압축, 반투명 합성, 차량 패널 밝기와 주변 조명까지 평가하는 값은 아니다.

| 대상 | 대비 |
|---|---:|
| 주 버튼 어두운 글자 / 라임 | 10.84:1 |
| 흰 글자 / 숯 바탕 | 17.84:1 |
| 본문 / 밝은 종이 | 16.59:1 |
| 보조 글자 / 밝은 종이 | 6.02:1 |
| 짙은 라임 글자 / 밝은 종이 | 5.91:1 |
| 어두운 글자 / 보조 버튼 | 14.38:1 |

### 확인한 문제

1. **해설 확대 화면 하단 문장 대비 저하.** `t038.png`와 `lotte-explain.png`에서 “중심과 바깥 기둥이 함께 힘을 나눠요”가 어두운 그라데이션 아래에 놓인다. 짙은 라임을 밝은 종이에 썼을 때의 대비가 실제 화면에는 유지되지 않는다. 원본 캡처의 y=1020 줄에서 배경 RGB(70,90,101)와 문자 RGB(22,50,47)를 표본으로 계산하면 약 1.90:1이다. 같은 그림이 작은 패널로 돌아오는 역할 놀이 화면에서는 문장이 더 밝고 선명하다. 읽기 전용으로 확인한 `MainActivity.kt`의 `scrim`은 장면 위 하단에 남아 있다. 코드 구현 담당이 해설 확대 상태에서의 겹침 처리를 확인해야 한다.
2. **밝은 사진 위 상단 흰 배지 대비 부족.** `t014.png`, `t086.png`, `t230.png`에서 경로 이름과 보호자 버튼의 흰 글자가 밝은 하늘 및 반투명 흰 배경과 겹친다. 숯 바탕일 때는 읽히지만 사진 위에서는 흐리다. 코드 구현 담당에게 보고하며 앱 코드는 수정하지 않았다.

### 별도 확인이 필요한 관찰

이번 자동 시연에서는 여의도, 숭례문, 광화문의 통과 후 해설 그림이 잠깐 나타난 뒤 역할 놀이로 넘어갔다. 여의도는 `part2.mp4` 시작 약 1~2초, 숭례문은 약 74~75초, 광화문은 약 146~147초 부근이다. `short-explain-transitions.mp4`는 각 구간 5초를 순서대로 모은 15초 증거 영상이다. 해설 그림의 사진과 색은 작은 패널에서도 확인했지만, 이 세 장소에서 확대 해설이 충분히 머물렀다고 평가하지 않는다. 녹화에 소리가 없으므로 실제 음성 생략 여부나 원인은 판단하지 않았고 구현 담당의 확인이 필요하다.

## 확인 범위

- 직접 실행한 것은 에뮬레이터 정차 시연, 화면 및 파일 확인, 빌드와 설치이다.
- 단위 검사 390개와 기기 검사 3종 통과는 구현 담당의 보고이다. 이번 촬영 작업에서 다시 실행하지 않았다.
- 실제 차량 주행, 낮/밤 차량 패널에서의 눈부심, 실제 아이의 음성 인식, 음성 청취 품질은 확인하지 않았다. 영상은 무음이다.

## 파일 확인 결과

- 최종 영상의 전체 디코딩 검사에서 오류가 없었다. 455초 프레임에서 청진옥 마무리 카드가 포함된 것을 확인했다.
- 내장 브라우저에서 발표자료 캡처 여섯 장이 모두 로딩되고, 영상이 오류 없이 실제 재생되어 재생 시간이 7초 이상 증가한 것을 확인했다.
- 녹화 파일을 바꾸는 명령 간 간격은 약 0.65초와 0.54초였다. 인코더 시작과 종료 지연도 있으므로 파일 경계는 완전히 연속된 프레임이라고 주장하지 않는다.
- 세 분할 녹화는 각 180초 제한이 끝난 뒤 가져왔다. 발표용 연결본에서는 마무리 카드 뒤의 긴 대기만 잘랐다. 원본 기기 해상도 파일은 작업 중 임시 경로 `/tmp/curator44-raw/`에 두었고, 저장소에는 앱 영역을 잘라 압축한 세 구간과 최종 영상을 남겼다.
