# 0.41.0 청진옥 재촬영

기준 커밋 `435e7e0`. 작업 시작 시 emulator-5554와 로컬 debug APK는 0.40.0(versionCode 42)이었다. 기준 소스에서 assembleDebug 후 설치하고 dumpsys package로 0.41.0(versionCode 43)을 확인했다.

## 사진

청진옥 질문과 설명 영상에서 일반 해장국 사진이 사라지고, 청진옥 간판이 보이는 1999년 골목 사진 한 장만 표시된다. 동그라미는 청진옥 간판을 가리킨다. 화면 캡처와 동영상 재생 장면을 실제로 확인했다.

## 만남 횟수: 저장값과 표시값의 차이 재현

`rounds.txt`는 기존 저장값 1에서 청진옥 구간을 한 번 진행한 기록이다. `t020.png`에는 정상적으로 `2번째 만남`이 표시된다. 같은 진행의 `t090.png`에는 `3번째 만남`이 표시되지만, 그 시점 XML의 `round:cheongjinok` 값은 2다. 저장값은 한 번만 증가했다. 문제는 중복 기록이 아니라 마무리 화면이 방금 증가한 저장값에 다시 1을 더해 보여 주는 것으로 보인다.

읽기 전용으로 확인한 MainActivity.kt:815는 render에서 `prefs.rounds(it.id)`를 읽고, 843~844는 FINISHED/READY 이외 단계에서 `say.meeting(met+1)`을 표시한다. 이 코드와 재현 화면은 같은 방문의 마무리 카드에서도 다음 방문 번호가 보이는 현상을 설명한다. 앱 코드는 수정하지 않았다.

## 이전 0.40.0 실행 명령 순서

1. 기존 데이터로 경로를 잠깐 시작했다가 캡처 스크립트를 Ctrl-C로 중단했다.
2. `adb shell pkill -INT screenrecord` 후 `adb shell pm clear --user 10 dev.changbak.explorer`가 Success를 반환했다.
3. `adb shell am start --user 10 -n dev.changbak.explorer/.MainActivity` 후 초기 화면에서 서울 경로 버튼 위치를 UI XML로 확인했다.
4. 새 Python 스크립트는 첫 screenrecord를 시작하고 2초 뒤 `adb shell input tap 2100 1060`을 단 한 번 실행했다. 이후 180초 녹화 3회와 12초 간격 screencap만 실행했으며 경로를 다시 누르는 명령은 없었다.
5. `fresh-t408.png`의 파일 시각은 2026-11-15 15:53:11 +0900, `fresh-t420.png`는 15:53:23 +0900이다. 파일명의 초는 캡처 번호이며 실제 경과 시간에는 ADB 명령 시간이 더해진다.

0.40.0 영상의 광화문 마무리 화면에서도 같은 경로 중 `2번째 만남`이 보인다. 따라서 이전 보고의 관찰은 유지하되 원인을 중복 집계로 해석하지 않는다.

## 범위

보호자 시점 이동으로 청진옥 약 5분 전을 선택한 뒤 재생했다. 실제 주행 검증이 아니며 소리는 녹화하지 않았다. 발표용 새 구간은 질문 초기화를 UI에서 확인한 후 별도로 재촬영했다. 다른 다섯 곳은 기존 0.40.0 자료를 사용한다.

추가 재현: 보호자 메뉴의 `질문을 처음 만남으로 되돌리기`를 누르고 확인창에서 `되돌리기`를 눌렀다. XML이 빈 map인 것을 확인한 뒤 청진옥 약 5분 전으로 이동해 한 번 재생했다. `fresh-t080.png`는 첫 진행의 마무리 화면에 `2번째 만남`을 표시한다. 같은 시점 `fresh-rounds.txt`의 값은 `round:cheongjinok = 1`이다. `fresh-validation.mp4`는 초기 질문부터 이 현상까지 담고 있다.

발표용 `cheongjinok.mp4`는 질문부터 역할 놀이까지 65초이고 `six-places.mp4`는 기존 다섯 장소 344초에 이 구간을 붙인 409초 편집본이다. 마무리 카드 표시 결함은 검증본에 보존했다. 발표자료에 구간별 버전과 시점 이동 촬영임을 표시했다. 실제 주행, 음성 입력과 청취 품질은 이번에도 확인하지 않았다.
