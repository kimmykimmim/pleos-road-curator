0.13.0 에뮬레이터 시연 결과: **기존 흐름 통과, 가족 기능 진입 실패, 가족 단계 음성 복구 미검증**.

| 검증 항목 | 판정 | 직접 관찰한 근거 |
|---|---|---|
| 1. 기존 자동 흐름 | **통과** | 한강의 과학 여행을 한 번 누른 뒤 109초 동안 추가 입력 없이 관찰. 01 → 02 → 03 → 04 순서 확인, 우리 가족의 기억 화면 없음. |
| 2. 가족의 기억 | **실패 / 후속 항목 차단** | 보호자 메뉴의 가족이 함께 갔던 곳 기록을 선택하면 메뉴가 닫히고 시작 화면이 남음. 장소 목록이나 기록 입력 화면에 도달하지 못함. |
| 3. 가족 단계에서 TTS 강제 종료 후 30초 내 복구 | **미검증 / 차단** | 가족 기록을 만들 수 없어 가족 단계에 진입하지 못함. TTS 엔진을 다른 단계에서 죽이는 것으로 대체하지 않았음. |

이 결과는 전체 기능 통과를 뜻하지 않는다. 가족 화면의 문구, 두 응답 버튼, 같은 장소에서의 중복 방지, 기록 삭제 후 단계 제거, 가족 단계 음성 실패 복구는 모두 재검증이 남았다.

가족 기록 진입에서 관찰한 실패

1. 보호자 버튼 (1020,100)을 누르면 메뉴가 나타나며, 네 번째 항목의 텍스트가 보였다 (`d-03-parent-menu.png`, `d-05-parent-retry.png`).
2. 네 번째 항목을 (430,256), 재시도에서는 텍스트 중앙 (332,259)로 눌렀다.
3. 첫 두 시도에서는 메뉴가 닫힌 시작 화면만 확인했고, 장소 선택 화면이 나타나지 않았다 (`d-04-family-menu-first-result.png`, `d-06-family-menu-retry-t000.png` 등).
4. 후속 시도에서는 입력과 화면 반영 지연이 발생했다. 예를 들어 보호자 버튼을 누른 후 캡처한 d-12에는 시작 화면이, 그다음 d-13에는 보호자 메뉴가 늦게 표시됐다. 이 구간은 정상적인 세 번째 재현으로 세지 않았다.
5. 최종적으로 보호자 메뉴가 표시된 상태에서 (332,259)를 다시 누르고 장시간 관찰했다. 입력 명령 완료는 시작 후 6.66초, 마지막 예약 +40초 캡처 완료는 +45.33초였으며, 여전히 시작 화면만 표시됐다 (`d-14-delayed-family-t40.png`).

**원인을 앱 하나로 확정할 수 없다.** 이 구간의 로그에는 `com.android.car.rotary`의 입력 ANR 및 이후 `com.google.android.gms` ANR이 있다. 특히 rotary ANR에는 실제 선택 좌표 `(332.0, 259.0)`의 MotionEvent를 약 5069ms 기다렸다는 내용이 기록됐다. 따라서 가족 기록 진입이 실패한 결과는 확인되지만, 앱 수정 전에 안정적인 에뮬레이터에서 다시 분리 재현해야 한다.

소스는 읽기만 했다. 원인 후보로는 `MainActivity.kt:160`의 `usable()`이 `dialog == null`을 요구하고, `:366`의 `show()`가 이 조건으로 반환하며, 이전 다이얼로그의 참조 해제는 `:369`의 dismiss 콜백에서 수행되는 점이 있다. 보호자 선택은 `:373`에서 handler.post로 새 메뉴를 호출한다. 기존 메뉴 dismiss 콜백보다 새 메뉴 요청이 먼저 실행되면 새 창이 버려질 가능성이 있다. **런타임 콜백 순서를 계측하지 않았으므로 이 부분은 추정이며 확정 진단이 아니다.**

환경 복구와 로그 판정

- 초기 설치 시 에뮬레이터의 패키지 서비스가 끊겨 `Broken pipe`가 발생했다. 서비스 복구 뒤 재설치에 성공했다.
- 기존 에뮬레이터는 `-no-audio`로 실행 중이었다. 이후 오디오 옵션을 제거해 재시작하고, 기본 흐름에서 한국어 TTS 합성 요청 7건을 확인했다. 실제 스피커 음성을 녹음하거나 청취해 검증한 것은 아니며, 새 가족 문장의 음성은 검증하지 못했다.
- 첫 재시작은 기존 `swiftshader_indirect` 렌더러를 사용했지만 그래픽 컨텍스트 오류와 QEMU 스레드 hang 후 호스트 에뮬레이터 프로세스가 종료 코드 139로 종료됐다. `d-emulator-swiftshader-crash.log`에 보존했다. 이는 앱 Java 예외와 별개의 호스트 프로세스 문제이다.
- 이후 `-gpu host -feature -Vulkan -no-metrics -crash-report-mode never`로 다시 실행했다. 크래시 보고서 업로드는 하지 않았다. 현재 해당 에뮬레이터 창과 앱은 열려 있다.
- 입력 지연 분리를 위해 `adb shell am force-stop --user 10 com.android.car.rotary`를 한 번 실행하고 앱을 다시 전면에 띄웠다. 소스나 앱 저장 기록을 조작하지 않았다. 그 뒤에도 가족 장소 목록에 도달하지 못했다.

| 로그 범위 | FATAL EXCEPTION | 기타 |
|---|---:|---|
| `d-validation-logcat.txt` — 정상 실행 후 초기화한 기본 흐름 로그 | **0** | 한국어 TTS 합성 요청 7건, ANR 언급 0건 |
| `d-family-validation-logcat.txt` — host 렌더러에서 가족 메뉴 검증 로그 | **0** | ANR 언급 3줄: rotary 사건의 두 로그와 GMS 사건의 한 로그. 앱 FATAL은 없음. |
| `d-host-boot-logcat.txt` — host 렌더러 부팅/앱 준비 | **0** | 검증 전 준비 로그 |
| `d-setup-logcat.txt` — 초기 연결 시 이미 남아 있던 누적 로그 | **29** | 01:56~02:19의 DeadSystem/UiAutomation 오류 등을 포함. 이번 정상 앱 시연 구간과 분리 보존. |

따라서 **이번 시연과 가족 메뉴 검증에서 수집한 logcat의 FATAL EXCEPTION은 0건**이다. 다만 환경 ANR 및 호스트 에뮬레이터 종료가 있었으므로, 이를 “오류가 전혀 없었다”로 표현하면 안 된다. 집계는 `d-log-summary.json`에 저장했다.
